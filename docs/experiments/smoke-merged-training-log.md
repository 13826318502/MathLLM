## 3. 判错样本分析

### 3.1 正方形坐标题：真实数学错误

标准答案为 `$(18,-18)$`，模型答案为 `$(18,-16)$`。

这不是 LaTeX 格式问题。正方形中心为 `(8,-8)`，面积为 `4`，因此边长为 `2`。顶部水平时，正确顶点应为：

```text
(7,-7), (9,-7), (9,-9), (7,-9)
```

经过原点、倍率为 `2` 的伸缩后，离原点最远的顶点是 `(18,-18)`。模型把中心坐标误当成了部分顶点坐标，属于几何建模错误。

### 3.2 帽子数量题：真实算术错误

模型的过程已经得到：

```text
总数 = 26 + 15 + 24 = 65
取走 = 4 + 6 + 2 × 6 = 22
剩余 = 65 - 22 = 43
```

但最终答案写成了 `53`。这不是 LaTeX 问题，而是最终计算结果与解题过程不一致。

### 3.3 组合数题：评测器误判

标准答案写作 `$\\binom52=10$`，模型写作 `$$\\binom{5}{2}=10$$`。两种写法数学含义相同，答案都是 `10`。

本题不是模型数学错误，也不是模型 LaTeX 错误，而是当前判分器没有把 `\\binom52` 和 `\\binom{5}{2}` 规范化为同一种表达式，导致程序误判为错误。

因此，本次 60% 的自动准确率被低估了 1 题。人工修正后，这 10 题实际约为 `7/10 = 70%`。

### 3.4 进制题：真实数学推理错误

题目中的 `33_b` 应表示：

```text
3b + 3
```

而不是模型使用的 `b^2 + 3b`。正确推导为：

```text
AAA_4 = 21A
33_b = 3b + 3
```

取 `A=1`、`b=6` 时，二者相等，且 `A+b=7`。模型误读了进制表示法，最终得到 `10`，属于数学推理错误，不是 LaTeX 格式错误。

## 4. LaTeX 和格式检查

本次 4 个判错项中，主要问题不是 LaTeX 格式：

- 2 个是数学推理或计算错误；
- 1 个是模型答案与过程不一致；
- 1 个是评测器未识别等价 LaTeX 表达式。

终端中部分中文显示为乱码，检查下载后的 UTF-8 JSON 后确认这是终端显示编码问题，不是这 4 道题的判错原因。模型整体能够输出步骤、公式和“最终答案”标记，过程完整性分数为 `0.90`，但过程完整不等于数学正确。

## 5. 实验结论

### 已验证通过

- LoRA 合并流程正常；
- 合并后的模型能够被 vLLM 加载；
- OpenAI 兼容接口正常；
- 测试请求全部成功；
- 评测程序能够保存模型答案、错题和延迟数据；
- 平均首 token 延迟为 `119.53 ms`，低于项目目标 `200 ms`。

### 尚未验证

- 10 条样本太少，不能代表最终准确率；
- 尚未与未微调基座模型进行同条件对比；
- 当前评测器仍需增强 LaTeX 等价表达式处理；
- 仍需人工复核完整测试集中的数学答案；
- 还不能据此判断是否达到项目设定的领域准确率目标。

## 6. 下一步

1. 修正判分器，使等价的 LaTeX 表达式能够正确匹配。
2. 检查并人工确认 `bad_cases.json` 中的真实错题。
3. 使用相同参数分别评测基座模型和 LoRA 合并模型。
4. 准备独立的 `test.json`，避免把用于选择 checkpoint 的验证集当作最终测试集。
5. 先跑完整测试集，再决定是否使用完整数据进行正式 LoRA 训练。
