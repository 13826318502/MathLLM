## 2. 合并后的评测结果

使用 llm-judge-retry-8-v2 重试后，得到：

第 63 条的最终直线方程正确，但中间投影系数写错。旧评测口径将其判为
reasoning_error；在新的最终答案准确率口径下，应重新评测并单独记录过程质量。

| 指标 | 合并结果 |

## 3. 主要错误领域

### 3.1 多步应用题、时间和单位关系：最高优先级

这是回归集中最集中的问题，常见错误包括：

- 把休息时间重复扣除或漏算；
- 没有区分“经过的总时间”和“实际工作时间”；
- 多步数量关系中漏掉一个加数或乘数；
- 没有正确理解题目中的人物、顺序和条件；
- 单位换算、取整和差值方向错误。

典型回归题包括第 5、8、12、22、26、27、28、34、35、42 条。
下一轮应重点训练“列出已知量—统一单位—逐步计算—最后核对”的完整过程。

### 3.2 代数推导、算术和数论：高优先级

主要表现为：

- 展开多项式时漏项或系数；
- 最大公约数的欧几里得变形不合法；
- 计算中漏掉因子、除数或边界；
- 取模问题中把“所有不同余数”误当成“前若干项”；
- 因式分解和指数运算中出现中间计算错误。

典型问题包括：

- 原始测试第 50 条：最大公约数推导错误，正确答案为 26；
- 原始测试第 92 条：把均值 -a/3 错当作 -a，正确答案为 -11；
- 原始测试第 106 条：错误地只求前 100 项，正确答案为 7；
- 回归集第 2、13、17、24、31、32、38、39 条。

这是目前最需要增加“相似但条件不同”训练题的领域。

### 3.3 线性代数：高优先级

错误集中在概念和矩阵操作：

- 分块矩阵行列式和伴随矩阵公式使用错误；
- 幂等矩阵的特征值集合与具体矩阵的特征值混淆；
- 把行变换解释成向量内积或错误的线性相关关系；
- 混淆共同特征向量、可交换和相似等概念；
- 投影公式中的比例系数计算错误。

典型问题包括：

- 原始测试第 12 条：分块矩阵伴随矩阵推导错误；
- 原始测试第 51 条：只回答特征值为 0，漏掉 1；
- 原始测试第 63 条：最终直线正确，但投影系数中间写错；
- 原始测试第 101 条：最终行列式答案正确，但解释行列式不变的理由错误；
- 回归集第 25、40 条。

下一轮不能只增加矩阵计算题，还要加入“判断概念、辨析错误证明、选择正确
性质”的样本。

### 3.4 概率、组合和计数：中高优先级

常见问题：

- 漏掉边界情况；
- 组合数上下标使用错误；
- 计数对象和排列顺序混淆；
- 只计算一种情况，没有验证所有情况；
- 概率分母与实际样本空间不一致。

回归集中的组合、除数计数和递推计数题仍有明显错误，说明模型需要更多带有
“分类讨论和结果自检”的样本。

### 3.5 三角函数、复数和其他专题：中等优先级

回归集还出现了：

- tan 周期方程变形错误；
- 复数旋转公式中旋转因子位置错误；
- 有理式展开和多项式恒等式计算错误；
- 数列和、几何量和函数题中的符号错误。

这些题目数量少于应用题和代数题，但适合在下一轮加入少量高质量专题样本，
防止模型只改善单一领域。

## 4. 这次问题不是哪些原因

目前证据不支持把主要问题归因于：

- vLLM 加载失败；
- CUDA OOM；
- tokenizer 不能处理 ChatML；
- 大量 LaTeX 格式错误；
- 全部由 JSON 评测失败造成。

本轮两组推理请求均已成功完成。评测 JSON 失败主要发生在独立 Judge 输出阶段，
不代表被测模型答案错误。旧报告中的 8 条原始测试失败和 6 条回归失败已经分别
完成重试；新提示词已经将评测输出简化为标签模式。

## 5. 下一轮微调数据安排

### 5.1 训练集

下一轮训练数据建议放入：

~~~text
data/raw/corrections/correction-round-4-training.jsonl
~~~

建议先准备约 100 条人工验算的同类型新题，比例可参考：

| 类型 | 建议数量 |
|---|---:|
| 多步应用题、时间、单位和数量关系 | 30 |
| 代数推导、算术和数论 | 25 |
| 线性代数 | 20 |
| 概率、组合和计数 | 15 |
| 三角函数、复数、数列和其他专题 | 10 |

这些题不能直接复制原始错题，应该改变数字、变量、条件或表述，训练解题方法
而不是记忆答案。source 必须使用 correction-round-4。

训练时仍要合并原始训练数据和纠错数据，不能只使用这 100 条纠错题：

~~~text
原始训练集 + correction-round-4-training.jsonl
~~~

### 5.2 训练期间验证集

新增一份不参与训练的纠错验证集：

~~~text
data/eval/correction-validation/round-4.json
~~~

建议准备 20 至 30 条与训练题不同条件的新题，用于观察纠错泛化和选择
checkpoint。原始 data/eval/test.json 和回归集不能用于 checkpoint 选择。

### 5.3 训练后测试集

保持以下数据独立：

~~~text
data/eval/test.json
data/eval/regression/regression.json
~~~

- test.json：衡量普通数学能力；
- regression.json：衡量历史错误是否复发，以及同类型题是否泛化。

原始错误题本身不能复制到 data/raw/corrections/。

## 6. 下一轮训练计划

### 第一步：固定新评测口径

先用修改后的 eval/llm_judge.py 对原始测试集和回归集完整重跑一次。新口径只
输出 correct、incorrect、uncertain，后续比较都使用同一套口径。

### 第二步：准备和验证纠错数据

1. 人工验算约 100 条 correction-round-4 样本；
2. 检查训练题与 test.json、regression.json 无重复；
3. 留出 20 至 30 条 correction validation；
4. 运行 scripts/prepare_data.py；
5. 检查 train/eval 数量、学科分布和重复题。

### 第三步：重新训练

由于 Correction Round 3 已经出现过拟合，下一轮不建议继续把
correction-round-3-merged 当作新的基座。更稳妥的对照方案是从原始 Qwen 基座
开始，用完整原始训练集加新纠错数据重新训练。

建议初始配置：

~~~yaml
num_train_epochs: 1
learning_rate: 5.0e-5
per_device_train_batch_size: 1
gradient_accumulation_steps: 8
eval_steps: 10
save_steps: 10
save_total_limit: 3
gradient_checkpointing: true
use_4bit: true
bf16: true
max_seq_length: 2048
load_best_model_at_end: true
~~~

每轮训练必须记录 train_loss、eval_loss 和最佳 checkpoint。若 train loss
继续下降而普通验证 loss 连续上升，应提前停止。

### 第四步：合并和评测

训练结束后：

1. 依据普通验证集和 correction validation 选择最佳 checkpoint；
2. 使用原始 Qwen 基座合并 LoRA；
3. vLLM 加载合并模型；
4. 使用相同生成参数运行 test.json 和 regression.json；
5. 用新版标签式 LLM Judge 重新评测两组；
6. 人工抽查所有 uncertain 和部分 incorrect。

建议的最低改进标准：

- 原始测试集准确率不能比当前基线下降超过 2 个百分点；
- 回归集准确率至少提高 10 个百分点；
- 不出现大量截断、重复或 HTTP 请求失败；
- LLM Judge 的 uncertain 比例控制在 5% 以下。

## 7. 结论

Correction Round 3 的总体能力没有明显提升，原始测试集在旧 LLM Judge 口径下约为
63.48%，回归集为 21.43%。主要短板是多步应用题、代数/数论和线性代数，
其次是概率组合及部分专题计算。

下一轮应采用“完整原始训练数据 + 分类纠错数据 + 独立纠错验证集”的方式，
从原始 Qwen 基座重新训练，降低学习率和 epoch，并使用新版只判断最终答案的
LLM Judge 统一比较。当前不建议量化或直接发布 Correction Round 3 模型。
