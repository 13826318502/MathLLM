# MathLLM 首次全量训练与评测实验报告

## 1. 实验概况

- 实验名称：首次完整训练、LoRA 合并、vLLM 推理与独立测试
- 训练日期：2026-09-03
- 复核日期：2026-09-04
- 训练平台：AutoDL，NVIDIA RTX 4090D 24GB
- 基座模型：Qwen2.5-7B-Instruct
- 微调方式：QLoRA 4-bit
- 推理模型：`outputs/math-lora-merged`
- 推理服务：vLLM OpenAI 兼容接口，端口 `8000`
- 独立测试集：`data/eval/test.json`，共 116 条

本报告记录的是首次完整实验，不代表最终发布模型质量。训练和评测产物保存在
本地或云端 `outputs/`、`eval/results/` 目录中，模型权重和逐题原始结果不提交到
GitHub。

gradient accumulation 8，并启用 QLoRA 4-bit 和梯度检查点。

基座模型合并生成独立模型。LoRA adapter 没有直接修改基座模型；合并模型是一个
新的可供 Transformers 和 vLLM 加载的模型目录。

## 3. vLLM 与推理链路

本轮合并模型成功由 vLLM 加载，并通过 `/v1/models` 和
`/v1/chat/completions` 接口验证。116 条基础评测请求全部完成，没有请求失败、
CUDA OOM 或模型服务中断。

这说明以下工程链路已经跑通：

```text
训练 → 保存 LoRA checkpoint → 选择最佳 checkpoint → 合并基座模型
→ vLLM 加载 → 批量推理 → 保存逐题结果 → 独立大模型语义评测
```

## 4. 首次基础评测结果

原始报告：`eval/results/final-test/report.json`

首次基础评测使用 `temperature=0`、`max_tokens=512`。

| 指标 | 结果 |
|---|---:|
| 测试样本 | 116 |
| 推理成功 | 116 |
| 推理失败 | 0 |
| 自动判断正确 | 65 |
| 自动判断错误 | 51 |
| 准确率 | `56.03%` |
| 平均总延迟 | `3338.56 ms` |
| 平均首 token 延迟 | `62.32 ms` |

这份 56.03% 是确定性的文本/数值匹配结果，不是最终语义准确率。它存在两个
影响因素：

1. 第 1 条题目当时的参考答案仍为 `$6$`，之后已根据“4 个检查点产生 3 个间隔”
   修正为 `$8$`；
2. `max_tokens=512` 对较长题目偏小，部分回答在完成最终答案前被截断。

因此不能直接把这 51 条全部视为真实数学错误。

## 5. LLM Judge 语义评测

全量语义评测使用独立的 DeepSeek OpenAI 兼容接口，模型为
`deepseek-v4-flash`。原始全量报告：
`eval/results/final-test/llm-judge-test/llm_judged_report.json`。

原始 LLM Judge 结果为：

| 标签 | 数量 |
|---|---:|
| correct | 74 |
| incorrect | 34 |
| uncertain | 8 |
| Judge 调用或解析失败 | 2 |

34 条确定错误中，LLM Judge 归类为：

- 推理错误：29 条；
- 答案错误：5 条。

两个失败项为第 66、101 条。它们的 API 请求本身成功，但评测模型在
`reasoning_content` 中输出了长篇分析，没有在 `content` 中完成最终 JSON。提高
输出上限并重试后，两条均成功完成评测：第 66 条为错误，第 101 条为正确。

为区分“模型确实不会”与“原评测输出被截断”，将原来 6 条不确定样本使用
`max_tokens=2048` 重新生成，并再次使用 LLM Judge 评测。

重测报告：

## 7. 综合结果

结合全量 LLM Judge、66/101 重测和 6 条截断样本重测，得到以下逻辑合并结果：

```text
正确：78
错误：38
不确定：0
评测失败：0
综合语义准确率：78 / 116 = 67.24%
```

这里的 67.24% 是根据多个结果目录合并计算的统计值，当前没有改写原始全量
`llm_judged_report.json`。因此：

- 原始全量报告中的 74/34/8/2 仍是当时的原始记录；
- 67.24% 是纳入全部重测后的修正统计；
- 两者不能混为同一份 JSON 报告。

## 8. 主要问题分析

本轮暴露的问题主要是数学推理和输出完整性，而不是部署链路问题：

1. 多步应用题中单位换算、取整和时间关系容易出错；
2. 概率与组合题容易漏情况或误用组合计数；
3. 线性代数题中共同特征向量、矩阵相似和行列式性质容易混淆；
4. 代数推导中容易漏掉系数或中途循环；
5. 复杂题目的回答容易在最终答案前被截断；
6. 某些结论虽然正确，但附加证明存在维度不严谨或无效反例。

### 当前结论

本项目的训练、部署和评测链路已经完整可运行，但模型当前约 67.24% 的综合语义
准确率仍不足以作为正式发布版本。当前结果适合作为第一轮基线和错误分析依据，
不应直接宣称模型已经达到专业数学助手水平。

### 下一步建议

1. 将 38 条真实错误按题型分类，构建同类不同条件的纠错训练样本；
2. 对训练集、验证集和测试集的参考答案继续人工验算；
3. 扩大高等数学、线性代数、概率论和多步应用题覆盖；
4. 保持同一份独立测试集，重新训练后使用完全相同的评测参数比较；
5. 在最终模型确定后，再进行 AWQ/INT4 量化和量化前后对比；
6. 正式报告中同时保留基础匹配指标、LLM Judge 指标和人工抽检结果。
