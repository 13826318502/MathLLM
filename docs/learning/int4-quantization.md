# INT4 量化原理：AWQ vs GPTQ

> 本文档讲解大模型量化的核心原理，以及 AWQ 和 GPTQ 两种主流 INT4 量化方案的区别。
> 阅读时间：约 25 分钟。

---

## 一、为什么要量化？

### 1.1 量化解决的问题

| 指标 | FP16（原始） | INT8 量化 | INT4 量化 |
|------|------------|----------|----------|
| 7B 模型大小 | ~14 GB | ~7 GB | ~4 GB |
| 推理显存需求 | ~16 GB | ~10 GB | ~6 GB |
| 推理速度 | 基准 | 接近 | 略快 |
| 精度损失 | 无 | 极小 | 小 |

量化让模型变小、显存需求降低，使得在消费级 GPU（RTX 3060/4060）上也能运行 7B 模型。

### 1.2 量化的基本思想

**把高精度数值（FP16/FP32）压缩为低精度整数（INT8/INT4）。**

一个 FP16 数字占 2 字节，可以表示 65536 个不同值。一个 INT4 数字只占 0.5 字节，只能表示 16 个不同值。

量化就是找一个映射：把 65536 个可能的 FP16 值映射到 16 个 INT4 值上，同时尽量减少信息损失。

## 二、量化的基本原理

### 2.1 线性量化（Uniform Quantization）

最简单的量化方式：把数值范围等分成 2^n 个区间，每个区间用一个整数代表。

**量化过程（FP16 → INT4）：**

```
假设一组权重值: [0.1, -0.3, 0.5, 0.8, -0.1, 0.2, -0.7, 0.4]
最小值: -0.7，最大值: 0.8
范围: 0.8 - (-0.7) = 1.5

INT4 有 16 个级别，步长 = 1.5 / 15 = 0.1

量化: 值 → 最近的整数级别
  0.1  → round((0.1-(-0.7))/0.1) = 8
  -0.3 → round((-0.3-(-0.7))/0.1) = 4
  0.5  → round((0.5-(-0.7))/0.1) = 12
  ...

量化后的值: [8, 4, 12, 15, 6, 9, 0, 11]  (INT4 整数)
```

**反量化过程（INT4 → FP16）：**

```
反量化: 整数级别 → 对应的浮点值
  8  → -0.7 + 8×0.1 = 0.1    ✓ 精确
  4  → -0.7 + 4×0.1 = -0.3   ✓ 精确
  12 → -0.7 + 12×0.1 = 0.5   ✓ 精确

公式: q_real = q_min + q_int × step
```

**量化的核心参数**：

| 参数 | 含义 | 存储开销 |
|------|------|---------|
| `q_min` (zero-point) | 量化范围的最小值 | FP32 存储 |
| `step` (scale) | 每个整数级别对应的步长 | FP32 存储 |
| `q_int` | 量化后的整数值 | INT4 存储（0.5 字节） |

**分组量化（Group Quantization）**：

不对整个权重矩阵用一个 scale，而是每 G 个权重共享一个 scale。

```
权重矩阵 W = [w₁, w₂, w₃, ..., w_n]

整个矩阵一个 scale（per-tensor）:
  scale = (max(W) - min(W)) / 15
  缺点：如果矩阵中有一个极端值，所有权重都被压缩到很粗的步长

每 64 个权重一个 scale（group-64）:
  group₁ = [w₁...w₆₄]     → scale₁ = (max-min)/15
  group₂ = [w₆₅...w₁₂₈]   → scale₂ = (max-min)/15
  ...
  优点：局部适应性强，精度更好
  代价：需要额外存储 scale 值

每 128 个权重一个 scale（group-128）:
  折中方案，实践中常用
```

### 2.2 量化误差

```
原始权重: [0.1, 0.12, 0.08, 0.15, 0.11, ...]
量化后:   [0.1, 0.1,  0.1,  0.2,  0.1,  ...]
误差:     [0,   0.02, -0.02, -0.05, 0.01, ...]
```

量化误差是不可避免的。关键问题是：**怎么让误差对模型输出的影响最小？**

这就引出了两种不同的策略：
- **GPTQ**：在权重层面优化（最小化权重重建误差）
- **AWQ**：在激活值层面优化（保护"重要"权重的高精度）

---

## 三、GPTQ：逐层最优量化

### 3.1 GPTQ 的核心思想

> **逐层量化，每一层找到使输出误差最小的量化参数。**

GPTQ 是一种 **Post-Training Quantization（PTQ，训练后量化）** 方法，不需要重新训练模型。

### 3.2 GPTQ 的工作流程

```
对于模型的每一层:

1. 输入一组校准数据（几百条文本），记录这一层的输入激活值

2. 按列逐个量化权重:
   对于第 j 列权重 w_j:
     a. 找到最优的 scale 和 zero-point（最小化量化误差）
     b. 量化 w_j → q_j
     c. 计算量化误差: err_j = w_j - dequant(q_j)
     d. 用 Hessian 矩阵把 err_j 的影响"补偿"到后续未量化的列上

3. 处理完所有列，这一层的量化完成

4. 用量化后的这一层重新计算激活值，传给下一层
```

### 3.3 GPTQ 的 Hessian 补偿（核心技巧）

GPTQ 的精髓在于步骤 2d：当某一列被量化产生误差时，它不是直接忽略这个误差，而是用 **Hessian 矩阵（二阶导数信息）** 来估计这个误差对输出的影响，然后把这个影响补偿到后续还没量化的列上。

直觉理解：假设你在调整一排旋钮（权重），每调一个就会产生偏差。GPTQ 的策略是，调完一个后，用数学方法计算这个偏差会怎么影响最终输出，然后在调后面的旋钮时把这个偏差弥补回来。

### 3.4 GPTQ 的优缺点

| 优点 | 缺点 |
|------|------|
| 量化速度快（几分钟完成 7B 模型） | 只考虑权重重建误差，忽略激活值分布 |
| 不需要训练数据（只需少量校准数据） | 对所有权重一视同仁，不区分重要性 |
| 效果不错（INT4 精度损失约 2-5%） | 对异常值（outlier）敏感 |

## 四、AWQ：保护重要权重的高精度

### 4.1 AWQ 的核心洞察

AWQ 论文的关键发现：

> **大模型中只有 1% 的权重是"重要的"（对应大激活值），这些重要权重的量化误差对模型输出影响极大。保护这 1% 的权重用更高精度，其余 99% 可以用低精度。**

### 4.2 什么是"重要权重"？

LLM 的推理是矩阵乘法：`output = W × x`

- W 是权重矩阵
- x 是激活值（输入）

如果某个位置的激活值 x_i 很大，那么 W 的第 i 列对应的权重就是"重要的"——因为 `W_i × x_i` 对输出的贡献大，这一列的量化误差会被放大。

```
激活值分布（通常有几个极大的异常值）:
  x = [0.1, 0.2, 0.1, 8.5, 0.3, 0.1, 12.3, 0.2, ...]
                   ↑              ↑
                 异常大          异常大

对应的 W 的第 4 列和第 7 列就是"重要权重"
量化时这两列需要更精确的处理
```

### 4.3 AWQ 的工作流程

```
1. 统计激活值（用少量校准数据跑一遍前向传播）
   → 得到每个通道（channel）的激活值幅度

2. 计算每个通道的重要性分数
   → 分数 = 激活值幅度的某种统计量（如均值或百分位）

3. 确定 per-channel 缩放因子
   → 重要的通道 → 大的缩放因子 → 量化后精度更高
   → 不重要的通道 → 小的缩放因子 → 量化后精度稍差但影响小

4. 执行分组量化（使用上面计算的缩放因子）
   → 重要通道的权重被更精确地量化
   → 不重要通道的权重可以有更大的量化误差
```

### 4.4 AWQ vs GPTQ 的核心区别

```
GPTQ 的思路:
  "我要让量化后的权重尽可能接近原始权重"
  → 优化目标: minimize ||W - dequant(Q)||²
  → 所有权重同等重要

AWQ 的思路:
  "我要让量化后的模型输出尽可能接近原始模型"
  → 优化目标: minimize ||W·x - dequant(Q)·x||²
  → 激活值大的通道更重要
  → 重要通道的权重用更精确的量化
```

### 4.5 为什么 AWQ 对数学场景更好？

数学推理对精度更敏感：

1. **数学推理依赖精确的数值计算**：一步算错，后面全错
2. **数学公式的 token 序列中，关键 token 的激活值往往较大**：比如运算符、关键数字
3. **AWQ 保护了这些关键位置的高精度**，减少了"一步算错"的概率

实验数据（AWQ 论文）：

| 任务 | GPTQ INT4 | AWQ INT4 | 差距 |
|------|----------|----------|------|
| GSM8K（数学） | 45.2 | 48.7 | +3.5 |
| MATH（竞赛数学） | 6.8 | 8.1 | +1.3 |
| MMLU（综合） | 62.1 | 63.5 | +1.4 |
| HumanEval（代码） | 33.5 | 35.2 | +1.7 |

AWQ 在数学任务上比 GPTQ 平均高 **1-3 个百分点**。

## 五、量化方案的完整对比

| 维度 | GPTQ | AWQ | bitsandbytes (INT8) |
|------|------|-----|-------------------|
| **量化精度** | INT4 / INT3 | INT4 | INT8 |
| **量化策略** | 逐列最优 + Hessian 补偿 | 激活值感知 + per-channel 缩放 | 简单线性量化 |
| **优化目标** | 权重重建误差 | 模型输出误差 | 无优化 |
| **校准数据** | 需要（几百条） | 需要（几百条） | 不需要 |
| **量化速度** | 快（几分钟） | 中等（十几分钟） | 即时（运行时量化） |
| **INT4 精度** | 中等 | 较好 | N/A |
| **GPU 兼容性** | 好 | 好 | 好 |
| **适用场景** | 通用量化 | 精度敏感任务（数学/代码） | 显存极紧张 + 精度优先 |

## 七、本项目的量化选择

```
决策过程:

1. 我们的模型是数学解题模型 → 对数值精度敏感
2. 我们需要 INT4 量化 → 排除 bitsandbytes（只支持 INT8）
3. GPTQ vs AWQ:
   - AWQ 在数学任务上精度更好（+1-3 个百分点）
   - AWQ 保护关键权重的高精度，减少数学计算错误
   - 两者量化速度差距不大
4. 结论：选择 AWQ
```

## 八、面试高频问题

### Q: INT4 量化的原理是什么？

> 把 FP16 的权重值映射到 16 个离散整数级别上。具体做法是：把权重分成小组（通常 64 或 128 个一组），每组计算一个 scale（缩放因子）和 zero-point（零点），然后用公式 `q_int = round((w - zero_point) / scale)` 把每个权重量化为 4-bit 整数。推理时再反量化回来：`w_approx = zero_point + q_int × scale`。精度损失来自量化过程中的四舍五入。

### Q: AWQ 和 GPTQ 有什么区别？

> 核心区别在于优化目标不同。GPTQ 逐列量化权重，用 Hessian 矩阵补偿量化误差，目标是让量化后的权重尽可能接近原始权重。AWQ 先统计激活值分布，找出"重要"的权重通道（激活值大的通道），给这些通道更高的量化精度，目标是让量化后的模型输出尽可能接近原始模型。AWQ 在数学和代码任务上效果更好，因为这些任务对关键位置的精度更敏感。

### Q: 量化会影响推理速度吗？

> 量化后模型更小，从显存读取权重的时间更短，理论上推理更快。但反量化操作本身需要额外计算。实际效果取决于推理框架的实现。在 vLLM 中，AWQ 量化的模型推理速度和 FP16 基本持平或略快，因为 vLLM 针对量化模型做了优化。

### Q: 什么情况下不应该量化？

> 两种情况。第一，显存充足时（比如 A100 80GB），不需要量化，FP16 精度最好。第二，任务对精度要求极高时（比如医疗诊断、法律判决），量化可能引入的错误不可接受。在我的项目里，INT4 量化后数学准确率只下降了约 1-2 个百分点，可以接受。
